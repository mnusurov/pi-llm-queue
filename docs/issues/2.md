# Issue 2: Tracer bullet: end-to-end serialisation of two sessions

State: OPEN · Labels: ready-for-agent

## Parent

#1 (Spec: pi-llm-queue)

## What to build

Two pi sessions talking to one model endpoint are strictly serialised: the second session's request waits while the first holds the slot, then hands over. Tracer bullet through all layers: daemon socket protocol, FIFO scheduler with `maxStreams: 1`, extension provider wrapper, daemon autostart.

## Acceptance criteria

- [ ] Daemon: unix socket, JSON protocol (`acquire`/`renew`/`release`/`status`), single queue keyed by endpoint baseUrl, `maxStreams: 1`, FIFO grants
- [ ] Extension: provider wrapper via `pi.registerProvider()` over a configured provider, delegating to the built-in openai-completions stream after slot grant; per-session lease client
- [ ] Daemon autostart from the extension: detached spawn, lockfile PID, stale-lockfile reclaim
- [ ] Fail-open: daemon unreachable → requests pass through
- [ ] Socket-seam test harness: two simulated sessions acquire alternately; second blocks while first holds; grant order asserted
- [ ] Tests MUST NOT hit the real model endpoint (stub/socket only)
- [ ] Dev note honoured: no parallel subagents in the implementing session until this ticket lands
