# Issue 2: Tracer bullet: end-to-end serialisation of two sessions

State: CLOSED · Labels: ready-for-agent

## Parent

#1 (Spec: pi-llm-queue)

## What to build

Two pi sessions talking to one model endpoint are strictly serialised: the second session's request waits while the first holds the slot, then hands over. Tracer bullet through all layers: daemon socket protocol, FIFO scheduler with `maxStreams: 1`, extension provider wrapper, daemon autostart.

## Acceptance criteria

- [x] Daemon: unix socket, JSON protocol (`acquire`/`renew`/`release`/`status`), single queue keyed by endpoint baseUrl, `maxStreams: 1`, FIFO grants
- [x] Extension: provider wrapper via `pi.registerProvider()` over a configured provider, delegating to the built-in openai-completions stream after slot grant; per-session lease client
- [x] Daemon autostart from the extension: detached spawn, lockfile PID, stale-lockfile reclaim
- [x] Fail-open: daemon unreachable → requests pass through
- [x] Socket-seam test harness: two simulated sessions acquire alternately; second blocks while first holds; grant order asserted
- [x] Tests MUST NOT hit the real model endpoint (stub/socket only)
- [x] Dev note honoured: no parallel subagents in the implementing session until this ticket lands

## Comments

Shipped on `feat/issue-2-tracer-bullet` (`3c4a2a4`, `241fff4`), reviewed two-axis (Standards,
Spec) against #1 and this ticket.

- `src/daemon.js` — unix socket, newline-JSON `acquire`/`renew`/`release`/`status`, FIFO
  scheduler, `maxStreams` per queue. Queue keys are endpoint baseUrls; a provider-name key
  resolves to that provider's baseUrl via `models.json`.
- `src/extension.ts` — `registerProvider` wrapper over every provider named by, or serving an
  endpoint named by, a `llm-queue.json` queue key; delegates to the built-in stream after the
  grant. Slot held for the whole run: acquire at `agent_start`, release 3 s after
  `agent_settled` (wake-chain grace), immediate on abort.
- `src/lease-client.ts` — per-session lease client, daemon autostart (detached spawn,
  `<socket>.pid` lockfile, socket-probe reclaim), fail-open when the daemon is unreachable.
- Tests (11, `make test`): `test/daemon.test.ts` (serialisation, FIFO order, disconnect drops a
  queued waiter, provider-name policy resolution, keyless status), `test/lease-client.test.ts`
  (fail-open, client-level serialisation, autostart, stale-lockfile reclaim),
  `test/extension.test.ts` (provider resolution). No real endpoint is touched.
- `node scripts/e2e-two-sessions.mjs` — human-run tracer bullet: two real pi sessions against a
  stub endpoint → `requests=2 overlaps=0 daemon-autostart=true`.

Not built (left in #1): priority tiers, aging, lease TTL/heartbeat, `blockSubagentLaunch`,
`/queue`, TUI indicator, idle-exit, config hot-reload. `renew` is a keepalive that answers `ok`
without expiring anything. Leases are tracked one per process, so a process running several
sessions (foreground children) needs per-session keys before #1's affinity stories are met.
